# Цифровой дизайнер презентаций

Веб-сервис, который разбирает .pptx-шаблон на дизайн-систему и по брифу и контент-пакету собирает три варианта презентации в стиле этого шаблона. Затем проверяет слайды аудитом и выгружает результат в .pptx, .pdf и .html.

> **Статус: рабочий макет.** Весь путь пользователя работает: аккаунты, шаблоны, генерация, выбор варианта, аудит, правка слайда из чата, экспорт. План колоды, тексты слайдов и правки из чата пишет LLM, паттерны шаблона размечает VLM, контекстуальные проверки аудита выполняет модель-судья (переменные `LLM_*`, `VLM_*`, `AUDIT_*`; без моделей колода собирается из тезисов брифа, работают правила). Не подключена text-to-image. Подробнее — в разделе [«Что работает, а что заглушка»](#что-работает-а-что-заглушка).

## Запуск

Нужен Docker (на Windows и macOS — Docker Desktop).

```bash
docker compose up --build
```

Первая сборка занимает несколько минут. После запуска:

- приложение — http://localhost:8080 (порт меняется переменной `APP_PORT`);
- документация API (Swagger) — http://localhost:8080/api/docs.

Готовых аккаунтов нет — зарегистрируйтесь. Шаблоны из папки `shablon/` готовы сразу: их разбор (паттерны и рендеры) лежит в `cache/` и раскладывается при старте за секунды. Свой шаблон разбирается при загрузке — минута-две на рендер.

**Как пройти весь сценарий:**

1. «Новая презентация» → выберите шаблон, введите название и бриф, при желании приложите файлы контент-пакета.
2. «Сгенерировать 3 варианта» — на экране видно, как идут стадии пайплайна (в макете около 15 секунд).
3. Выберите вариант.
4. На шаге аудита отметьте замечания и нажмите «Исправить».
5. Скачайте результат в .pptx, .pdf или .html.

Настройки задаются в файле `.env` (необязательно, у всех переменных есть значения по умолчанию):

```bash
cp .env.example .env
```

### Режим разработки

В этом режиме бэкенд, воркер и фронтенд перезапускаются при изменении кода, а порты базы данных и Redis доступны с хоста:

```bash
docker compose -f docker-compose.yml -f docker-compose.dev.yml up --build
```

- фронтенд (Vite) — http://localhost:5173;
- API — http://localhost:8000/api/docs;
- PostgreSQL — `localhost:5432` (пользователь `app`, пароль `app`, база `slides`), Redis — `localhost:6379`.

Фронтенд можно запустить и без Docker, если API работает на порту 8000:

```bash
cd frontend && npm install && npm run dev
```

## О приложении

### Экраны

- **Вход и регистрация.**
- **Главная** — мои презентации и библиотека шаблонов.
- **Шаблон** — результат декомпозиции: паттерны слайдов (слайды-примеры с разметкой слотов), палитра, шрифты, типографическая шкала, макеты и их роли. Здесь же можно загрузить свой .pptx.
- **Настройки генерации** — шаблон, название, назначение (фича, продукт, проект, инициатива), бриф, контент-пакет, число слайдов, язык, тон, ось различий вариантов, заметки докладчика, генерация изображений.
- **Генерация** — ход стадий пайплайна и версии скиллов, которыми собрана колода.
- **Выбор варианта** — три варианта рядом, просмотр всех слайдов, рерол варианта (кубик) — пересборка с другими паттернами шаблона. Превью — это рендеры того же .pptx, что уйдёт в экспорт.
- **Аудит** — замечания подсвечены прямо на слайде. Пользователь отмечает, что исправить автоматически, а что скрыть. Отдельная вкладка — каталог всех проверок.
- **Экспорт** — скачивание .pptx, .pdf и .html.
- **Общий доступ** — владелец создаёт ссылку с ролью «редактор» или «наблюдатель». По ссылке могут присоединиться только авторизованные пользователи; новым пользователям показывается регистрация. Владелец меняет роли, отзывает доступ и ссылки, а уведомления о приглашении и изменении роли появляются под колокольчиком в шапке. После сохранения изменений открытые у участников страницы автоматически обновляются через SSE, без перезагрузки браузера.

### Архитектура

| Сервис | Стек | Роль |
|---|---|---|
| `frontend` | React 19, TypeScript, Vite, TanStack Query; nginx | интерфейс; nginx раздаёт статику и проксирует `/api` на бэкенд |
| `backend` | FastAPI, SQLAlchemy 2 (async), Alembic, LibreOffice (headless) | REST API: аккаунты, шаблоны, презентации, аудит, экспорт; рендер .pptx в PDF |
| `worker` | arq, LibreOffice (headless) | фоновые задачи: разбор шаблонов с рендером макетов и пайплайн генерации |
| `db` | PostgreSQL 16 | пользователи, шаблоны, презентации, прогоны генерации, варианты, замечания аудита |
| `redis` | Redis 7 | сессии пользователей и очередь задач |

Загруженные файлы лежат в Docker-томе `storage`. Встроенные шаблоны монтируются из `shablon/` только для чтения.

Авторизация построена на серверных сессиях в Redis: токен хранится в httpOnly-cookie, пароли — в виде хеша Argon2. Для скриптов и CLI тот же токен приходит в ответе `POST /api/auth/login` и принимается в заголовке `Authorization: Bearer <token>`.

### Пайплайн генерации

Стадии выполняет воркер. Прогресс сохраняется в БД и публикуется в Redis; интерфейс получает его по SSE, а если поток оборвался — опрашивает API раз в 5 секунд.

1. **Декомпозиция шаблона** (`pipeline/parsing`) — паттерны слайдов-примеров, тема, фактическая палитра, шрифты, кегли, макеты, их роли и цвет фона (подробнее — в разделе «Парсер шаблонов»).
2. **Анализ контент-пакета** (`pipeline/content`) — извлечение текста из файлов и выдержки для промптов.
3. **Генерация структуры** (`planning/planner.py`) — LLM строит план колоды: состав слайдов, их тип, вывод каждого и факты из брифа и материалов, которые обязаны на нём оказаться.
4. **Тексты слайдов** (`planning/writer.py`) — LLM пишет содержимое каждого слайда сразу в структуре вёрстки (тезисы, карточки, колонки, числа, этапы, таблица, цитата), по запросу на слайд параллельно.
5. **Вёрстка трёх вариантов** (`pipeline/layout`). Варианты различаются по оси, которую выбирает пользователь: плотность контента, способ визуализации данных, порядок и группировка слайдов или выбор макетов. Каждому слайду подбирается паттерн шаблона (`layout/matcher.py`).
6. **Графики, таблицы и инфографика** (`pipeline/visuals`) — правила `skills/visualizer.yaml`: тип диаграммы по данным (доли — круговая, динамика во времени — линия, длинные подписи — горизонтальные столбцы), сортировка рейтингов, акцент на ключевой категории (её называет автор текстов), округление, единицы, объём таблиц, KPI и этапов, порядок этапов по датам; затем паттерны шаблона перепроверяются. При сборке — подпись с единицей, формат чисел, приглушённые неключевые столбцы, числа в таблицах по правому краю. 7. **Изображения**.
8. **Сборка слайдов по шаблону** — варианты собираются в .pptx (клоны слайдов-примеров + макеты) и рендерятся LibreOffice в превью. Вместе с картинками сохраняются факты для аудита: строки текста PDF, шрифты, цвета, кегли, картинки и логотипы каждого слайда.
9. **Аудит** (`pipeline/audit`) — проверки по данным, по рендеру и моделью-судьёй. Судья читает тексты колод параллельно рендеру, после рендера смотрит на слайды с иллюстрациями.

Стадии длятся ровно столько, сколько идёт их работа: время каждой видно на экране генерации.

Промпты и параметры скиллов и агентов хранятся в YAML-файлах в `backend/skills/`, у каждого файла есть версия. При каждом прогоне генерации сохраняется снимок версий всех скиллов, он показан на экране генерации.

Слайд описывается моделью `Slide` (`backend/app/schemas/slide.py`): тип, тексты, данные для визуализации, паттерн (`pattern_id`) и ключ макета шаблона. Эту модель используют генерация, аудит, экспорт и фронтенд.

### Тексты: план колоды и содержимое слайдов

Текстовые стадии работают на одной открытой модели (проверено на Qwen3.8-27B через RouterAI; подойдёт любой OpenAI-совместимый `/chat/completions`).

1. **План колоды** (`planning/planner.py`) — один запрос: состав слайдов, тип каждого, группа, приоритет, тема, вывод и `must_include` — факты и цифры из брифа и материалов, которые обязаны попасть на слайд. Модель выбирает тип только из тех, что умеет вёрстка, и предпочитает типы, для которых у шаблона есть слайды-примеры, — план строится под возможности конкретного шаблона.
2. **Тексты слайдов** (`planning/writer.py`) — запрос на слайд, параллельно. Для каждого типа своя JSON-схема ответа, поэтому модель не может вернуть лишнее: карточки — заголовок и фраза, данные — категории и ряд чисел, таймлайн — этапы. Для «гибких» слайдов модель пишет тезисы, карточки и колонки сразу — три варианта вёрстки показывают один смысл по-разному без новых запросов.
3. **Нормализация** — число тезисов и длина фразы по `skills/slide_writer.yaml`, ряды диаграммы подрезаются под категории, таблица строится из тех же чисел. Если модель смешала единицы измерения в одной диаграмме, числа показываются карточками, а не графиком.
4. **Отказоустойчивость** — обрыв связи повторяется один раз, обрезанный лимитом ответ — с удвоенным лимитом; слайд без ответа остаётся с фактами из плана, а колода без модели целиком собирается по детерминированному сценарию. Стоимость стадии (модель, число запросов, токены) видна в подписи к стадии генерации.

План прогона сохраняется у генерации: рерол варианта пересобирает вёрстку из него, не обращаясь к модели заново.

### Парсер шаблонов

Дизайн корпоративных шаблонов живёт в основном не в макетах, а в слайдах-примерах: в VK Tech 36 из 54 слайдов лежат на одном «свободном» макете и нарисованы фигурами (до 258 фигур на слайде). Поэтому парсер разбирает каждый слайд-пример в **паттерн**, а генерация клонирует подходящий пример и заполняет его слоты — так слайды выглядят как сам шаблон, а не как текст на фоне.

1. **OOXML-разбор** (`pipeline/parsing/template_parser.py`, `patterns.py`) — детерминированный, без привязки к конкретному шаблону:
   - тема, палитра, шрифты, кегли, фоны, макеты и их роли — как раньше;
   - группы раскрываются с учётом трансформаций (`chOff/chExt`), для каждой фигуры — абсолютная геометрия, кегль, начертание, текст;
   - **серии** — повторяющиеся тексты одного кегля и начертания с близкой высотой рамки (допуск, а не точное совпадение: высота зависит от длины текста-примера); серия-якорь (заголовки карточек) собирает вокруг себя остальные серии и декор: подложки, иконки, номера;
   - **роли слотов**: заголовок, текст, заголовок+текст, строки списка, показатель, подпись, дата, номер (1, 2, 3… по порядку), основной текст, подзаголовок, место под картинку; у каждого слота — ёмкость в знаках при его кегле;
   - **декор, привязанный к слоту** — маркеры строк, иконки, плашки: удаляются вместе со слотом, если его нечем заполнить;
   - **тип паттерна**: карточки, две колонки, KPI, шаги/таймлайн, оглавление, таблица, текст, текст с изображением (плюс служебные: схема, люди, сложный);
   - **назначение слайда**: контент, обложка, разделитель, финал, визитка, пример кода, цитата, витрина иконок — под контент идут только контентные.
2. **Рендер** (`pipeline/parsing/renders.py`) — LibreOffice одним прогоном рисует слайды-примеры и фоны макетов: превью на странице шаблона и вход для VLM.
3. **VLM-разметка** (`pipeline/ai/vlm.py`, необязательно) — модель видит рендер слайда и таблицу фигур с ролями по правилам и уточняет тип, назначение и роли. Геометрию она не придумывает: ответ ссылается только на существующие id фигур, проверяется схемой и порогом уверенности; при ошибке или недоступности модели остаются правила. Подходит любой OpenAI-совместимый `/chat/completions` с картинками и открытыми весами ≤ 35B: Qwen3.8-27B на своём vLLM/SGLang, Qwen3.6-35B-A3B в Yandex AI Studio или Cloud.ru (примеры — в `.env.example`).
4. **Подбор паттерна** (`pipeline/layout/matcher.py`) — по типу содержимого, числу элементов и ёмкости слотов; лишние элементы штрафуются, повторы тоже. Варианты A/B/C берут разных кандидатов из равноценных, рерол — случайного. Если ничего не подходит, слайд верстается на макете, как раньше.
5. **Сборка** (`pipeline/export/pattern_fill.py`) — клон слайда-примера со всеми фигурами, картинками, фоном; текст подставляется с форматированием самого слота (шрифт, кегль, цвет, маркеры, интервалы), лишние элементы удаляются целиком, текст примера не остаётся; таблицы подстраиваются под данные с сохранением стиля. Для подсветки аудита сборка возвращает рамки элементов.

Что ещё извлекает парсер (версия 0.5):

- **Любой формат шаблона** (`parsing/formats.py`) — .pptx, .potx, .pptm, .potm, .ppsx, .ppsm приводятся к .pptx заменой типа основной части пакета (макросы удаляются), .ppt, .pot, .pps, .odp, .otp конвертирует LibreOffice. Так же обрабатываются встроенные шаблоны в `shablon/`.
- **Паттерны из макетов** (`parsing/layout_patterns.py`) — для шаблонов почти без слайдов-примеров (типичный .potx): макет с заголовком и несколькими областями даёт «две колонки», «сравнение» с подзаголовками, сетку карточек, «текст с картинкой». Слайд создаётся на макете, текст ставится в плейсхолдеры и наследует их стиль; при равенстве подбор предпочитает слайды-примеры.
- **Служебные паттерны** — обложка, разделитель и финал из слайдов-примеров своей категории: оформление на самом слайде (фото, графика) сохраняется, номер раздела ставится в его «01».
- **Диаграммы шаблона** — у примеров с диаграммой записываются тип, число рядов и категорий; при сборке диаграмма копируется вместе с данными и стилями и получает новые данные (`replace_data`), поэтому график выглядит как в шаблоне, а не как стандартный.
- **Токены дизайн-системы** (`parsing/design_tokens.py`): типографика по ролям (заголовок, подзаголовок, текст трёх уровней, подпись — гарнитура, кегль, начертание, цвет, интервал); сетка (поля, направляющие PowerPoint, линии колонок); колонтитулы, номер слайда и логотипы; стиль таблиц и цвета рядов диаграмм шаблона; доступность шрифтов для рендера (fontconfig) и библиотека пиктограмм. Сборка переносит номер слайда и колонтитул на новые слайды, новые таблицы берут стиль таблиц шаблона, диаграммы — цвета его рядов, текст на макетах — кегли его типографики.
- **Схема слотов** у каждого паттерна (`schema`) — сколько знаков в заголовке и тексте, сколько элементов допустимо: по ней LLM сможет писать текст сразу под выбранный паттерн.
- **Устойчивость** — ошибка на одном слайде или макете чужого шаблона не роняет разбор: такой слайд помечается `error` и в генерацию не идёт.
- **Кэш разбора** (`services/template_cache.py`) — результат по встроенным шаблонам лежит в `cache/` и при старте раскладывается по хранилищу, поэтому проект поднимается с готовыми паттернами и рендерами без LibreOffice и без запросов к VLM. Ключ — хеш файла шаблона: другой файл, другая версия парсера или другая модель разметки — разбор с нуля. На загруженные шаблоны кэш не распространяется: свой шаблон (и незнакомый шаблон на защите) всегда проходит полный разбор с рендером и VLM.

Результат виден на странице шаблона («Паттерны слайдов» с разметкой слотов поверх рендера и «Дизайн-система» с токенами, предупреждением о недоступных шрифтах и пиктограммами) и в превью вариантов. Версия парсера хранится у шаблона: при её смене встроенные шаблоны разбираются заново перед генерацией, а превью старых вариантов пересобираются в фоне.

### Что работает, а что заглушка

| Часть | Состояние |
|---|---|
| Аккаунты, шаблоны, презентации, очередь задач | работает |
| Декомпозиция шаблона | работает: паттерны слайдов-примеров со слотами, назначением и типом (правила), рендеры слайдов и макетов; VLM-разметка подключается переменными `VLM_*`. Роли макетов — по использованию, плейсхолдерам и названиям |
| Контент-пакет | из txt, md, csv, pdf, docx и pptx извлекается текст; xlsx и json сохраняются, но пока не читаются |
| Структура и тексты | работает на LLM (`LLM_*`): план колоды одним запросом, затем запрос на слайд параллельно. Модель выбирает тип слайда из тех, что умеет вёрстка, и предпочитает типы, для которых у шаблона есть слайды-примеры; ответ проверяется JSON-схемой и нормализуется по ограничениям `skills/slide_writer.yaml`. Без модели, при её ошибке или обрыве колода собирается из тезисов брифа как есть — без придуманных фактов |
| Три варианта вёрстки | работает по правилам из `skills/layout_composer.yaml`: слайды получают паттерны шаблона, варианты и рерол различаются паттернами. Модель пишет содержимое слайда сразу в трёх формах (тезисы, карточки, колонки), поэтому варианты показывают один смысл по-разному без новых запросов |
| Графики, таблицы, инфографика | работает по правилам `skills/visualizer.yaml` (стадия генерации, рерол и правка из чата) |
| Правка слайда из чата | работает на LLM (`planning/editor.py`, промпт `skills/slide_editor.yaml`): модель переписывает слайд по сообщению, тип и оформление сохраняются, текст укладывается в ёмкость слотов паттерна; ответ модели показывается в чате |
| Изображения | **заглушка**: готовятся промпты, на слайде — плейсхолдер |
| Аудит | в каталоге `skills/auditor.yaml` 34 проверки, все выполняются: 10 — по данным слайда и шаблона, 14 — по собранному .pptx и его рендеру (геометрия строк текста, шрифты, кегли, цвета, логотипы, заполненность), 9 — моделью-судьёй по тексту колоды, 1 — судьёй по картинкам слайдов. Вердикты судьи кэшируются по отпечатку слайда, после правки проверяется только изменённое. Без модели 4 контекстуальные проверки идут по запасным правилам. Для 19 проверок есть автоисправление: новый текст пишет модель, остальное — правила |
| Экспорт .pptx | работает: слайды с паттерном — клоны слайдов-примеров шаблона с заполненными слотами; остальные — на макетах шаблона нативными объектами (тексты, диаграммы, таблицы, фигуры) |
| Экспорт .html | работает: автономный файл из рендеров собранного .pptx (текст слайдов — скрытым блоком для поиска), без рендеров — на фонах макетов; слайды листаются стрелками |
| Экспорт .pdf | работает: рендер собранного .pptx через LibreOffice, оформление шаблона совпадает один в один. Без LibreOffice (локальный запуск без Docker) — упрощённый запасной рендер |
| Превью слайдов в интерфейсе | рендеры того же .pptx, что уйдёт в экспорт; замечания аудита подсвечиваются рамками элементов из сборки. После правок и рерола превью пересобирается в фоне, а пока — приближение на HTML поверх рендера макета |

Куда подключать модели:

- LLM для структуры, текстов и правки слайда — `backend/app/pipeline/planning/`, промпты в `skills/outline_planner.yaml`, `skills/slide_writer.yaml`, `skills/slide_editor.yaml`;
- VLM для разметки паттернов шаблона — переменные `VLM_*` (`backend/app/pipeline/ai/vlm.py`, промпт в `skills/template_parser.yaml`);
- модель-судья аудита — переменные `AUDIT_*` (`backend/app/pipeline/audit/review.py`, промпты и каталог в `skills/auditor.yaml`);
- text-to-image — стадия `images` в `backend/app/pipeline/orchestrator.py`, промпт в `skills/image_generator.yaml`.

Ограничения: интерфейс рассчитан только на десктоп (по ТЗ); свой шаблон загружается в форматах .pptx, .potx, .pptm, .potm, .ppsx, .ppsm, а .ppt, .pot, .pps, .odp, .otp — через конвертацию LibreOffice. Если шрифта из шаблона нет в системе, LibreOffice подставит похожий — фирменные шрифты положите в `backend/fonts/` (подробности в `backend/fonts/README.md`).

## О кейсе

**Кейс 14 · «Цифровой дизайнер презентаций»** — хакатон «Лидеры цифровой трансформации» 2026, номинация «Медиаконтент», заказчик — VK Tech (AI-продукты). [Страница задачи](https://i.moscow/hackaton/lct/a964db5a6bd444a6bc5981770f55a080) · полное ТЗ — [`4. VK Tech.pdf`](4.%20VK%20Tech.pdf).

**Задача.** Open-source сервис (AI-пайплайн), который анализирует шаблон презентации — структуру, дизайн-систему, типовые паттерны слайдов — и по предоставленному контенту сам создаёт новую презентацию в стиле этого шаблона, без ручного редактирования. Результат должен подтверждать, что система адаптируется к стилю произвольного шаблона, а не работает по заранее зашитым сценариям.

**Ресурсы от организаторов:** Inference API для доступа к LLM, 3 шаблона разных стилей, 1 набор контента, CLI для разработки и интеграции.
